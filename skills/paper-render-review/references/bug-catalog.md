# The bug catalog: triage, matching, recording, fixing by recipe

The catalog turns every review into input for the next one. A finding is a single observation; a **bug** (`RB-####`) is the reusable knowledge: what students see, why it happens, how to recognise the next occurrence, and how to fix it. The next paper's findings that match a bug arrive with their fix recipe already attached.

## Where it lives

- Private: `neet-qa-platform/paper-review/catalog/bugs.jsonl` (occurrences name real question ids). `CATALOG.md` next to it is generated by `paperqa catalog render`; never hand-edit it.
- Public (this repo): the schema ([../catalog-template/bug.schema.json](../catalog-template/bug.schema.json)), the finding schema, and seed entries with synthetic repros only ([../catalog-template/seed-bugs.jsonl](../catalog-template/seed-bugs.jsonl)).
- One JSON object per line, ordered by id, append-only. Bugs are never deleted: they become `duplicate` (with `duplicate_of`), `false-positive`, `wontfix` or one of the `fixed-*` states.

## Matching a finding (deterministic)

For each finding `f` (from `findings.jsonl`) and each bug `b`:

1. `f.check` must be in `b.signature.checks`.
2. Every constraint that is present must hold:
   - `fields`: `f.field` matches one of them (`option:*` matches any option);
   - `evidence_regex`: matches `f.evidence.snippet + " " + json(f.evidence.metrics)`;
   - `raw_regex`: matches the raw bank field `f` points at;
   - `paths`: contains the review's path or `any`;
   - `app_sha_range` `A..B`: the pin is at or after `A`. If the pin is at or after `B` (the fix), the match is reported as **REGRESSION of b**, which is always a blocker for the app team.
3. Score = number of constraints present. The highest score wins; ties go to the lower id.

`paperqa merge` writes `catalog_match` on each finding, and `triage.md` groups findings by bug: matched bugs first (with recipe), then new findings, then regressions.

## Triage of a new finding

1. Look at the evidence in this order: screenshot → `pages/<n>.html` → `pipeline.jsonl` (normalised and rendered fields) → raw bank row. Confirm on the device result, not only Chromium.
2. Decide real vs `HARNESS.FALSE_POSITIVE`. For a false positive, fix the check (thresholds in references/checks.md) and add a probe self-test or static fixture case, then add a `false-positive` catalog entry so the same pattern auto-matches until the fixed check ships.
3. Pick the category whose **fix playbook** you will follow. A bug belongs to exactly one category.
4. Find the root-cause layer with evidence. Code causes get `code_refs` as `repo:path:line@sha`.
5. Write the synthetic repro: the smallest hand-written input that triggers the same checks. Never real question text.
6. Write the signature as narrow as possible while still matching this finding. Check it with `paperqa catalog match --bug RB-#### --runs last:5`: it must match this finding and must not match findings already attributed to other bugs.
7. Write the fix recipe so someone else can apply it without asking you: exact before → after, and a `data_transform` when it is mechanical.

## Writing a good entry

| Field | Good | Bad |
|---|---|---|
| `title` | "Match table collapses into one line on the live exam" | "rendering issue in Q14" |
| `signature` | `{"checks": ["D-MATCH-LAYOUT", "S-TYPE-NOT-ON-PATH"], "paths": ["live"]}` | `{"checks": ["D-RAW-LATEX"]}` with no constraint, for a bug that is really about `\begin{matrix}` |
| `root_cause.explanation` | "The exam-time payload has no type, so `classifyType` returns UNKNOWN and `extractStructure` never runs (`live_test_mapper.dart:100@8672b249`)." | "app bug" |
| `fix.recipe` | "Replace the stem's Column I / Column II prose with `<table><thead><tr><th>Column I</th><th>Column II</th></tr></thead>...` keeping labels A-D and I-IV in the cells." | "fix the table" |
| `fix.workaround_for_old_builds` | "Data fix above; the app fix (send and read `question_type` on the live path) only reaches app >= 1.1.42." | empty, when the store build lacks the fix |

## Changing the taxonomy

A new category is justified only when no existing category's fix playbook applies. Open the PR in this public repo first (taxonomy + a synthetic example + the check mapping), then sync the file into `neet-qa-platform/paper-review/taxonomy/`. Never rename or reuse an id; retire with `retired` and `superseded_by`. A new check id needs: the taxonomy row, a section in references/checks.md, an implementation, and a self-test case.

## Fixing similar bugs by recipe

When a new paper's finding matches a bug with `fix.kind = data`:

1. `paperqa fix plan --run <run>` collects every matched finding whose bug has a `data_transform`, applies the transform to the raw field **in memory**, and writes `fixes/<paper>/fixes.json` (before sha256, after value, bug id, finding ids).
2. It re-renders the planned after-values (`--override`) through static + DOM (+ device for blockers) and drops any planned fix that does not clear its findings or that creates new ones. Those go back to triage.
3. A human reads the plan and the before/after screenshots and runs `apply.py --commit` (safety-and-data.md). The agent never applies it.
4. Every applied fix adds an `occurrences` entry with `resolution: "fixed in data <date> by <name>"`.

When the bug's `fix.kind` is `app` / `backend` / `importer`, the occurrence is recorded, the workaround is staged as data if the store build lacks the fix, and the bug's `prs` list tracks the code change.

## Common recipes (keep in sync with the seed entries)

| Category | Data recipe | Code fix (where) |
|---|---|---|
| `MATH.PARSE_ERROR` (`\,^\circ`) | `s/\\,\^/\\,{}^/g` inside math | app: `fixMathSpacingScripts` already does it; a hit means an old build or a variant |
| `MATH.PARSE_ERROR` (script without base) | `$^2$` → `${}^{2}$` | |
| `MATH.SILENT_TRUNCATION` | `%` → `\%` inside math | |
| `MATH.BAKED_RESIDUE` | replace the whole `.katex` block with `$<tex>$` (from the source paper if no annotation) | importer: never store rendered KaTeX |
| `MARKUP.MARKDOWN_LITERAL` | `**x**` → `<b>x</b>`; `![](u)` → `<img src="u">` | importer: emit HTML; app: markdown is not supported |
| `MARKUP.LINE_BREAKS_LOST` | meaningful `\n` → `<br>` | importer |
| `MARKUP.STYLE_STRIPPED_LAYOUT` | flex/grid divs → `<table>` | importer |
| `MARKUP.TAG_DROPPED` (`<u>`) | `<u>NOT</u>` → `<b>NOT</b>` | app: allow `u` in the sanitizer, with a test |
| `STRUCT.TYPE_MISSING_ON_PATH` | MATCH → stem `<table>`; AR / statements → `<b>` labels + `<br>` before each | backend: send `question_type` in the exam paper; app: read it in `paperQuestionFromJson` |
| `MEDIA.OPTION_IMAGE_DROPPED` | option `text` = `<img src="<image>">` (+ the text) | app: carry `image` in the live mapper and render option images |
| `MEDIA.IMAGE_NOT_SHOWN` | wrap the URL in `<img src="...">` or move it to the image column | app: widen `linkifyImageUrls` (case-insensitive, allow `?query`, markdown images) |
| `LAYOUT.HEIGHT_TRUNCATED` | crop or downscale the image; split the passage | app: raise the clamp only with a device test on the texture limit |
| `LAYOUT.HORIZONTAL_CLIP` | break long formulas (`\\` in `aligned`, shorter fractions) | app: `overflow-x: auto` on inline math wrappers, with a 360 dp test |
